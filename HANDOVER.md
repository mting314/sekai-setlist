## What this repo is

`mting314/sekai-setlist` is a standalone copy of [the-sorter](https://github.com/hamproductions/the-sorter)
(full history, `upstream` = hamproductions/the-sorter). It's not a GitHub fork because
`mting314/the-sorter` already is one, and GitHub allows only one fork per account. It carries the
**Project Sekai setlist builder** at `/sekai-setlist`, ported from `sekai-story-indexer`.

| Branch               | Contents                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `main`               | the-sorter `upstream/main` at the time of the port (`dc1ec8e`) — no Sekai code             |
| `feat/sekai-setlist` | the port + this handover + the e2e script. Merge into `main` once the browser checks pass. |

## What's done and verified (without a browser)

- Page: `src/pages/sekai-setlist/`, components `src/components/sekai-setlist/`, logic
  `src/utils/sekai-setlist/`, types `src/types/sekai.ts`, nav entry in `src/pages/+Layout.tsx`,
  EN/JA strings under `sekaiSetlist.*`.
- Catalog: `data/sekai/{songs,units,characters}.json` (721 songs), regenerated by
  `bun scripts/fetch-sekai-songs.ts`. `data/sekai/` is outside what `update-data.yml` writes.
- Assets: jackets hotlinked from `https://storage.sekai.best/sekai-jp-assets/music/jacket/<b>/<b>.webp`
  with `referrerPolicy="no-referrer"` (the CDN 403s third-party Referers — confirmed with curl:
  200 without Referer, 403 with a github.io Referer). Unit + vocalist icons bundled in
  `public/assets/sekai/{units,chara}/*.webp`.
- Features: search (JP title / kana reading / EN name), unit filter (6 units + Other, OR-ed),
  commissioned vs cover, bag mode with per-song encore toggle, exact-order mode with dnd-kit
  (pointer + keyboard sensors, sortable encore divider, duplicate songs supported), localStorage
  save slots, lz-string share link in `#s=…`.
- Past setlists at `/sekai-setlist/lives` (`PastSetlists.tsx`, `src/utils/sekai-setlist/lives.ts`):
  COLORFUL LIVE, Anniversary Thanks Festival, Sekai Symphony, Connect Lives and 2026 unit fan
  meetings from `data/sekai/lives.json`, generated by `bun scripts/fetch-sekai-lives.ts` from the
  Project SEKAI fandom wiki (parser: `live-wikitext.ts`) plus hand-entered
  `data/sekai/lives-manual.json` (fan meetings: schedule from LiveFans, setlists not yet known). Series filter plus the same
  search / unit / commissioned-cover filters, a "Most performed" view, and "Open in builder" per
  setlist (encodes it as a `#s=` link to `/sekai-setlist`). Lives without a setlist show "No setlist yet";
  re-run the script once the wiki posts their setlists.
- `bun check` green; 54 vitest tests pass (`bun node_modules/vitest/vitest.mjs run src/utils/sekai-setlist`).
- SSR HTML renders both pages and the nav link; icon URLs return 200.

**Not verified:** anything that needs a rendered browser — images actually painting, filters
changing the list, drag and drop, clipboard, share-link round trip, slots, phone layout.

## Setup

```bash
git clone https://github.com/mting314/sekai-setlist && cd sekai-setlist
git checkout feat/sekai-setlist
bun install
bunx playwright install chromium        # playwright is already a devDependency
lsof -iTCP:3000 -sTCP:LISTEN            # make sure no other Vite server is on :3000
bun dev                                 # serves http://localhost:3000 (Vike rejects --port)
```

Toolchain notes: there may be no `node` on PATH — run everything through bun. Lint with
`bun check` (or `bun node_modules/oxlint/bin/oxlint src`; not `bun x oxlint`). Two Vite servers
bound to IPv4/IPv6 :3000 cause "stale code / empty list" red herrings.

## Task 1 — run the scripted Chromium test

```bash
bun scripts/e2e/sekai-setlist.e2e.ts            # headless, desktop 1280×900 + iPhone 13
HEADED=1 bun scripts/e2e/sekai-setlist.e2e.ts   # watch it
```

It prints PASS/FAIL per check, writes screenshots to `test-results/sekai-setlist/`, and exits
non-zero on failure. Checks: nav link; result count; jackets loaded + `no-referrer`; unit and
vocalist icons loaded; Leo/need, Leo/need+Other, Other, Commissioned, Covers counts (computed from
`songs.json`); EN-name search; duplicate add; keyboard drag (desktop) and pointer drag (phone) in
exact-order mode; share link → fresh context round trip (title + order); save / New / load /
delete slot; no horizontal overflow on phone; no console errors; no HTTP ≥ 400.

The script was written blind (it has never run). Expect to fix selectors or timing first — fix
the **script** when it's wrong about the UI, fix the **app** when the UI is wrong. Then open every
screenshot and look at it: layout, image quality, truncation, dark-on-dark text.

## Task 2 — agentic exploratory pass

Drive the page with a browser agent (Playwright MCP, `meta browser`, or ad-hoc scripts) and try
to break it. At minimum:

1. **Phone (≈390px) and small phone (360px):** search dialog fits (`100dvh`), unit chip row
   scrolls horizontally without pushing the list, rows don't overflow, touch drag works via the
   grip handle and the page still scrolls elsewhere (`touchAction: none` is only on handles).
2. **Encore:** bag mode ✦ toggle moves songs between Main/Encore; exact-order mode dragging the
   divider and dragging songs across it; switching modes back and forth preserves the encore split.
3. **Limits:** add up to `maxSongs` (50) and confirm Add disables/stops; search result cap
   (200 shown + "refine your search" note).
4. **JA locale** (`localStorage.i18nextLng = 'ja'`): JP titles shown, unit names translated,
   nothing untranslated or clipped.
5. **Dark mode** and light mode: unit-color chips and badges stay readable.
6. **Jacket failure:** block `storage.sekai.best` (route abort) — rows should fall back to the
   unit-color tile, no layout jump, no console spam.
7. **Share links:** open a `#s=` URL on first visit (cold load), a corrupt `#s=garbage` (should
   load empty, not crash), and a link containing a song id that no longer exists in the catalog.
8. **Keyboard / a11y:** tab through the editor and dialog, Escape closes the dialog, focus returns
   to "Add songs", drag handles have labels.

9. **Past setlists** (`/sekai-setlist/lives`): series / unit / kind filters narrow the live list
   and dim non-matching rows in an expanded setlist; Encore/Intermission dividers sit in the right
   place; "Most performed" counts change with the filters; "Open in builder" loads that setlist
   (title, order, encore) in the builder; JA shows `nameJa` and JP titles.

Record findings as a short list; fix what's clearly a bug, ask about anything that's a design call.

## Task 3 — make this repo deployable (ask before enabling)

GitHub Actions are **disabled** on this repo (Settings → Actions) because the inherited
workflows would misfire here:

- `deploy.yml` builds with `PUBLIC_ENV__BASE_URL=/the-sorter`; this repo's Pages path is
  `/sekai-setlist`. Update both occurrences, then test the page under that base path
  (`PUBLIC_ENV__BASE_URL=/sekai-setlist bun run build && bun run preview`) — bundled icons go
  through `getAssetUrl`, jackets are absolute.
- `update-data.yml` (12-hourly cron) needs `INTERNAL_REPO_TOKEN` for private scripts — disable or
  delete it here.
- `tweet.yml` posts to X on `v*` tags — delete it here.
- `ci.yml` is fine to keep.

Then run the e2e script against the deployed URL:
`BASE_URL=https://mting314.github.io/sekai-setlist bun scripts/e2e/sekai-setlist.e2e.ts` — this
is the real test of the no-referrer jacket fix, since localhost Referers aren't blocked.
